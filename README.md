# Dice Grid

Локальная и онлайн браузерная настольная игра на поле 6×6 с двумя кубиками. Игроки по очереди бросают кубики, выбирают одну из двух координат и стремятся первыми собрать три свои фишки подряд.

## Технологии

- React + TypeScript + Vite
- Socket.IO (онлайн-комнаты)
- Vitest
- Общая игровая логика в `shared/game`

Сервер хранит комнаты в памяти (без базы данных).

## Установка

```bash
npm install
```

## Запуск локально

Одновременно поднимаются Vite (порт 5173) и игровой сервер (порт 3001):

```bash
npm run dev
```

Откройте `http://localhost:5173`.

### Локальная игра

На стартовом экране сначала укажите **имя**, затем:

- **С друзьями** — hotseat на одном устройстве (2–4 игрока).
- **С компьютером** — вы против 1–3 ботов (2–4 игрока за столом). Сложность: лёгкий / средний / сложный.

После броска и после хода есть короткая пауза, чтобы все успели увидеть результат.

Только сервер:

```bash
npm run server
```

## Онлайн с друзьями через ngrok

1. Запустите игру: `npm run dev`
2. В другом терминале пробросьте фронтенд (Socket.IO проксируется Vite на бэкенд):

```bash
ngrok http 5173
```

3. Откройте выданный HTTPS-URL, создайте комнату и отправьте другу **код комнаты**.
4. Друг открывает тот же URL → «Войти по коду».

Опционально можно задать прямой URL сервера:

```bash
VITE_SERVER_URL=https://your-server.example.com npm run dev
```

По умолчанию клиент использует тот же origin и ходит в `/socket.io` через proxy.


После `build` один процесс (`npm start`) отдаёт и игру, и Socket.IO на порту `PORT` (по умолчанию 3001).

## Деплой на Railway

Рекомендуемый вариант: **один сервис** (фронт + сервер вместе).

### 1. GitHub

```bash
git init
git add .
git commit -m "Initial commit: Dice Grid online"
gh repo create dice-board-game --private --source=. --remote=origin --push
```

Или создайте репозиторий на github.com и:

```bash
git remote add origin https://github.com/<you>/dice-board-game.git
git push -u origin main
```

### 2. Railway

1. Зайдите на [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo**.
2. Выберите репозиторий.
3. Railway подхватит `railway.json`:
   - Build: `npm install && npm run build`
   - Start: `npm start`
4. В настройках сервиса включите **Generate Domain** (Public Networking).
5. `PORT` Railway выставит сам — сервер его уже читает.

Откройте выданный URL (`https://….up.railway.app`) — это и сайт, и WebSocket. Друзьям достаточно ссылки и кода комнаты; ngrok больше не нужен.

### Замечания

- Комнаты в памяти: при рестарте сервиса все комнаты сбрасываются.
- `VITE_SERVER_URL` для Railway **не нужен**, если фронт и API на одном домене.
- Альтернативы с той же схемой «один Node-процесс»: Render, Fly.io, VPS.

## Режимы игры

### Локально (hotseat)

Все игроки за одним устройством, как в первой версии. Доступна панель «Режим тестирования».

### Онлайн

1. Создать комнату (2–4 игрока) или войти по коду.
2. Дождаться заполнения лобби.
3. Хост нажимает «Начать игру».
4. Ходы делает только текущий игрок; состояние синхронизируется с сервера.
5. После победы новую партию запускает хост.

Сессия комнаты сохраняется в `sessionStorage` для переподключения при обновлении страницы.

## Правила

1. Перед партией определяется первый игрок: все бросают кубики, большая сумма ходит первой; при ничьей — переброс среди лидеров.
2. В свой ход нажмите **Бросить кубики**.
3. Два значения образуют координаты `(A,B)` и `(B,A)`. При дубле — одна клетка `(A,A)`, и после действия игрок бросает ещё раз (пока выпадают дубли).
4. Пустая клетка — поставить фишку; чужая — удалить; своя — недоступна.
5. Победа: 3+ своих фишек подряд (горизонталь / вертикаль / диагонали), только после установки.
6. В лобби (и перед локальной игрой) можно выбрать цвет фишки из палитры.
